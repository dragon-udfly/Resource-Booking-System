# Hall Booking Application Process: பயனர் வழிகாட்டி

## அறிமுகம்
இந்த ஆவணம் Resource Booking System-க்குள் ஒரு Hall Booking விண்ணப்பத்தின் முழுமையான வாழ்நாள் சுழற்சியை விவரிக்கிறது. இது சமர்ப்பிப்பு, பல அடுக்கு ஒப்புதல் பணிப்பாய்வு, ரத்துசெய்தல் கொள்கைகள் மற்றும் சிறப்பு நிர்வாக நடவடிக்கைகளை உள்ளடக்கியது.

---

## 1. விண்ணப்பம் சமர்ப்பித்தல் (Application Submission)
**பங்கு:** Requester (எந்தவொரு அதிகாரியும்) அல்லது Admin (ஒரு அதிகாரியின் சார்பாக).

*   **செயல்முறை:**
    *   **Halls > Book Hall**-க்கு செல்லவும்.
    *   ஒரு மண்டபம், தேதி மற்றும் நேரத்தைத் தேர்ந்தெடுக்கவும்.
    *   நிகழ்வு விவரங்களை நிரப்பவும் (பங்கேற்பாளர்கள், நிரல் போன்றவை).
    *   **Emergency Check:** "Emergency Booking" என்று குறிக்கப்பட்டால், கணினி உடனடியாக கோரிக்கையை *தானாக அங்கீகரிக்கிறது* (கைமுறை மதிப்பாய்வைத் தவிர்க்கிறது).
*   **விளைவு:**
    *   விண்ணப்ப நிலை `Pending` என அமைக்கப்படுகிறது (அவசரம் இல்லாவிட்டால்).
    *   Audit Log உள்ளீடு உருவாக்கப்பட்டது: *"New Hall Booking Application [ID] submitted"*.

---

## 2. ஒப்புதல் பணிப்பாய்வு (Approval Workflow)
கணினி ஒரு **வரிசையான 3-அடுக்கு ஒப்புதல் படிநிலையை** செயல்படுத்துகிறது. ஒரு விண்ணப்பம் இந்த கட்டங்களை வரிசையாக கடந்து செல்ல வேண்டும்:

### Tier 1: Administrative Officer (AO)
*   **செயல்:** ஆரம்ப கோரிக்கையை மதிப்பாய்வு செய்கிறார்.
*   **விருப்பங்கள்:**
    *   **Approve:** `administrative_officer_approved` ஐ `Approved` என அமைக்கிறது. விண்ணப்பத்தை Tier 2 க்கு நகர்த்துகிறது.
    *   **Reject:** நிலையை `Rejected` என அமைக்கிறது. செயல்முறை முடிகிறது.

### Tier 2: Additional Government Agent (AGA)
*   **செயல்:** AO-வின் ஒப்புதலை சரிபார்க்கிறார்.
*   **விருப்பங்கள்:**
    *   **Approve:** `additional_government_agent_approved` ஐ `Approved` என அமைக்கிறது. விண்ணப்பத்தை Tier 3 க்கு நகர்த்துகிறது.
    *   **Reject:** நிலையை `Rejected` என அமைக்கிறது. செயல்முறை முடிகிறது.

### Tier 3: Government Agent (GA)
*   **செயல்:** இறுதி அதிகாரம்.
*   **விருப்பங்கள்:**
    *   **Approve:** `government_agent_approved` ஐ `Approved` என அமைக்கிறது.
        *   **விளைவு:** `final_approval` நிலை `Approved` ஆகிறது.
        *   **Email Trigger:** கணினி தானாகவே விண்ணப்பதாரருக்கு **"Hall Booking Approved"** மின்னஞ்சலை அனுப்புகிறது.
    *   **Reject:** நிலையை `Rejected` என அமைக்கிறது.
        *   **விளைவு:** `final_approval` நிலை `Rejected` ஆகிறது.

## 3. ரத்துசெய்தல் கொள்கை (Cancellation Policy)
ரத்துசெய்தல் விதிகள் பயனர் பாத்திரம் மற்றும் முன்பதிவின் தற்போதைய நிலையைப் பொறுத்தது.

### A. Requester (விண்ணப்பதாரர்)
*   **விதி:** **அனைத்து** ஒப்புதல்களும் இன்னும் `Pending` ஆக இருந்தால் மட்டுமே ரத்து செய்ய முடியும்.
*   **கட்டுப்பாடு:** AO (Tier 1) அதைச் செயல்படுத்தியவுடன், கோருபவர் கணினி வழியாக ரத்து செய்ய முடியாது.

### B. Administrative Officer (AO)
*   **விதி:** இன்னும் இறுதி செய்யப்படாத (அதாவது, `final_approval` `Pending`-ல் உள்ள) முன்பதிவை மட்டுமே ரத்து செய்ய முடியும்.

### C. Government Agent (GA)
*   **விதி:** **Approved** முன்பதிவை ரத்து செய்யலாம் (Revoke).
*   **செயல்முறை:**
    *   ஏற்கனவே அங்கீகரிக்கப்பட்ட முன்பதிவில் GA "Cancel" என்பதைத் தேர்ந்தெடுக்கிறார்.
    *   **ரத்து செய்வதற்கான காரணத்தை** (Reason for Cancellation) வழங்க வேண்டும்.
*   **விளைவு:**
    *   `final_approval` `Cancelled` என அமைக்கப்படுகிறது.
    *   **Email Trigger:** காரணத்துடன் விண்ணப்பதாரருக்கு கணினி **"Hall Booking Cancelled"** மின்னஞ்சலை அனுப்புகிறது.

---

## 4. நீக்குதல் (Data Cleanup)
நீக்குதல் என்பது தரவுத்தளத்திலிருந்து பதிவை நிரந்தரமாக நீக்குகிறது.

*   **Requesters:** கண்டிப்பாக `Pending` (இன்னும் நடவடிக்கை எடுக்கப்படவில்லை) ஆக இருந்தால் மட்டுமே தங்கள் விண்ணப்பங்களை நீக்க முடியும்.
*   **Admins/Approvers:**
    *   **கடந்த கால நிகழ்வுகளை** (History cleanup) நீக்கலாம்.
    *   இனியும் தேவைப்படாத **நிராகரிக்கப்பட்ட** விண்ணப்பங்களை நீக்கலாம்.
    *   **தடை:** செயலில் உள்ள, அங்கீகரிக்கப்பட்ட வரவிருக்கும் முன்பதிவை முதலில் ரத்து செய்யாமல் நீக்க முடியாது.

---

## 5. மறு ஒப்புதல் (Re-Approval) - (GA Only)
**காட்சி:** ஒரு முன்பதிவு முன்பு ரத்து செய்யப்பட்டது அல்லது நிராகரிக்கப்பட்டது, ஆனால் மீண்டும் நிலைநிறுத்தப்பட வேண்டும்.

*   **பங்கு:** Government Agent (GA) மட்டும்.
*   **முரண்பாடு சரிபார்ப்பு:** இதற்கிடையில் அந்த தேதி/நேரத்திற்கு மண்டபம் *வேறொருவரால்* முன்பதிவு செய்யப்பட்டுள்ளதா என்பதை கணினி தானாகவே சரிபார்க்கிறது.
    *   *முரண்பாடு இருந்தால்:* மறு ஒப்புதல் தடுக்கப்படும்.
    *   *கிடைத்தால்:* மறு ஒப்புதல் தொடர்கிறது.
*   **விளைவு:**
    *   நிலை `Approved` என மீட்டமைக்கப்படுகிறது.
    *   நிராகரிப்பு காரணம் அழிக்கப்படுகிறது.
    *   **Email Trigger:** **"Hall Booking Approved"** மின்னஞ்சலை மீண்டும் அனுப்புகிறது.

## சுருக்க அணி: செயல்கள் & மின்னஞ்சல்கள்

| செயல் | செய்தவர் | மின்னஞ்சல் அனுப்பப்பட்டதா? | குறிப்புகள் |
| :--- | :--- | :--- | :--- |
| **Submit** | Requester | No | - |
| **Approve** | AO / AGA | No | உள் நிலை புதுப்பிப்பு மட்டும். |
| **Approve** | **GA** | **YES** | இறுதி ஒப்புதல் அறிவிப்பு. |
| **Reject** | Any Approver | No | டாஷ்போர்டில் நிலை Rejected எனக் காட்டுகிறது. |
| **Cancel** | Requester / AO | No | நிலுவையில் உள்ள கோரிக்கைகளுக்கு மட்டும். |
| **Cancel** | **GA** | **YES** | உறுதிப்படுத்தப்பட்ட முன்பதிவை ரத்து செய்தல். |
| **Re-Approve** | **GA** | **YES** | இடம் காலியாக இருந்தால் முன்பதிவை மீண்டும் நிலைநிறுத்துகிறது. |
